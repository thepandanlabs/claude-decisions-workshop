# Block 5 — Pick Your Track

**Time:** 01:40 – 01:50
**Goal:** Every attendee leaves with a clear next step — one extension track chosen, and a starting prompt either already pasted into Claude Code or saved for the evening.

## The four tracks

Each one extends the `decisions` tool you built today. Pick by what you'd actually use — not by what sounds impressive.

| Track | What it is | What it unlocks | Time at home |
|---|---|---|---|
| **A — Scheduled briefing** | Tool emails a weekly report every Monday at 8am automatically. | Status updates write themselves. Never manually compile a week-in-review again. | An evening. |
| **B — Drive / Notion sync** | `decisions add` pulls transcripts directly from a connected Google Drive folder or Notion database. | No more manual export. New transcript drops in → ledger updates automatically. | A weekend. |
| **C — Slack watch** | An agent monitors a Slack channel where your team drops meeting notes. New message → automatic processing. | Zero manual trigger. Post the notes, the ledger updates. | A weekend. |
| **D — MCP + Claude Desktop** | Plug the tool into Claude Desktop as a built-in capability. | Ask Claude: *"What's still open from the SAMA partnership meeting?"* — real ledger query, real answer. | An evening. |

Full briefs for each track are in the [extension tracks section](../index.html#tracks) of the home page.

## What to say in this block

Read aloud:

> *"You ran the tool, you saw the gaps, you closed one of them, you verified it. The same loop scales to anything. The four tracks are not difficulty levels — they're four different shapes of useful. Pick the one closest to how you'd actually use this every week."*

Then:

> *"In the next five minutes, open the track page, read the brief, copy the starting prompt, and paste it into a fresh Claude Code session in your repo. Don't run `/implement` yet — just get the plan. We'll wrap with what people see."*

## What attendees do

1. Open the track page from the home grid.
2. Read the one-paragraph brief.
3. Copy the starting prompt.
4. Open a fresh Claude session in their repo.
5. Enter Plan Mode (Shift+Tab twice).
6. Paste the prompt.
7. Read the plan that comes back.

Stop there. Don't approve. Don't implement. The plan itself is the takeaway — a 5-minute glimpse of what an evening of building looks like.

## Common questions in this block

- **"Can I pick two?"** Pick one for this week. Add the second next week. Track A and Track D are an evening each — you can do both by the weekend.
- **"What if I want to build something entirely different?"** Same loop. Write a PRD for your idea. Write a CLAUDE.md with the rules for your domain. Run `/plan` → `/implement` → verify. The `decisions` tool was the worked example, not the limit.
- **"Which track is best for non-technical people?"** Track A (scheduled briefing) — one working evening, no APIs, the output is an email you already know how to read. Track D (MCP) is the most *powerful* for day-to-day use once it's set up.
- **"Do I need to know how to code to do these?"** No. You need to know what you want. The PRD and CLAUDE.md carry the knowledge; Claude Code carries the execution.

## Facilitator note — read the room

If two minutes in, half the room is still scrolling through tracks without committing, lean in:

> *"Pick the one that solves the problem you felt most acutely in the last month. The plan is free — you can throw it away."*

If the room is moving fast and everyone's on a track by 01:43, use the extra minutes for the Q&A you parked in Block 1.

## Outputs from this block

- Every attendee has opened a track page, copied a starting prompt, and read a plan from Claude.
- Every attendee leaves with a concrete next step that isn't *"explore Claude Code more."*
